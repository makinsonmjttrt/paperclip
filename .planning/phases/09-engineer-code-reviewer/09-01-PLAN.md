## FPZ Implementation Workflow

When assigned implementation issues:

1. **Understand the issue:** Read the issue description, labels, and any CTO comments for architectural guidance. If the CTO has provided a technical approach, follow it.

2. **Check the codebase:** Read existing code in the affected area before writing new code. Match existing patterns. The ADHD EF system is a Next.js app -- check `src/` structure, existing components, and API routes.

   - Create a feature branch: `feat/{issue-slug}` or `fix/{issue-slug}`

   - Keep PRs focused -- one concern per change
   - Test what matters: business logic, API endpoints, data transformations

   - Push branch and create PR via `gh pr create`
   - Write a clear description: what changed, why, how to test
   - Reference the originating issue

5. **Hand off to Code Reviewer:**
   - Create a review issue assigned to Code Reviewer with the PR link
   - @-mention Code Reviewer on the originating issue
   - Set originating issue status to `in_review`
   - Wait for review feedback before merging

6. **After review:**
   - Address any requested changes from Code Reviewer
   - Once approved, merge the PR
   - Mark the originating issue as `done`
   - Comment with a summary: branch, PR number, what shipped

8. **UK English.** Variable names and comments in UK English where applicable ("colour" not "color").
