Content for CMO:

```
## 3.9 Issue Size Check (LOAD-03)

Before delegating an issue, assess whether it should be split into sub-issues:

1. Read the issue title and full description.

2. **Split if ANY of these conditions are true:**
   - Description references 3+ distinct deliverables (e.g., "write blog post, create LinkedIn post, and update website copy")
   - Issue has been `in_progress` for 3+ heartbeats without completion (check comment timestamps against heartbeat frequency)
   - Description contains work types that map to 2+ different reports (e.g., content production + SEO audit = Technical Writer + UX Researcher)

3. **If splitting:**
   a. Identify each distinct deliverable or work stream
   b. Create one sub-issue per deliverable:
      `POST /api/companies/{companyId}/issues`
      - Set `parentId` to the original issue ID
      - Set `goalId` to the original issue's goalId
      - Set `assigneeAgentId` to the correct report for that deliverable (see Direct Reports table in section 4)
      - Copy ONLY the relevant portion of the brief for that sub-issue (not the whole description)
      - Start with: `[BRIEF-PASSTHROUGH] Split deliverable from issue #{parentId}:`
   c. Comment on the original issue:
      `[LOAD-SPLIT] Split into {count} sub-issues: #{id1}, #{id2}. Each covers a distinct deliverable. Parent closes when all children are done.`
   d. Set original issue status to `in_progress` (tracking parent)
   e. Skip section 4 Delegation for this issue (sub-issues are already delegated)

4. **If NOT splitting:** proceed to section 4 Delegation as normal.

5. **Do NOT split if:** the issue is large but all work maps to a single report. Splitting adds overhead without benefit in that case.
```
