2. Add a new unnumbered reference section "## Weekly Utilisation Report" after the "Workload Balance Check" reference section (added by Plan 01) and before "Data Scope Audit". Content:

```
## Weekly Utilisation Report

**Trigger:** Run ONLY if today is Monday OR if `last_weekly_report` in MEMORY.md is 7+ days ago OR `last_weekly_report` is `never`. Skip entirely if neither condition is true.

### Generate Report (CONS-01)

1. Read "## Weekly Snapshot" from MEMORY.md to get last week's baseline lifetime counters.
2. Read current Performance Metrics from all 14 agents' MEMORY.md files (same path pattern as Company Health Summary).
3. For each agent, calculate weekly deltas:
   - `weekly_output` = current `output_count` - snapshot `output_count`
   - `weekly_heartbeats` = current `heartbeats_total` - snapshot `heartbeats_total`
   - `weekly_heartbeats_with_work` = current `heartbeats_with_work` - snapshot `heartbeats_with_work`
   - `weekly_util` = round(weekly_heartbeats_with_work / weekly_heartbeats * 100) if weekly_heartbeats > 0, else 0

4. Classify each agent:
   - If weekly_heartbeats == 0 AND lifetime heartbeats_total < 5: status = `NEW` (not yet activated)
   - If weekly_util < 20 AND weekly_heartbeats >= 5: status = `UNDERUTILISED`
   - Otherwise: status = `OK`

5. Write report to today's daily notes under "## Weekly Utilisation Report":

   | Agent | Weekly Output | Weekly Heartbeats | Weekly Util % | Status |
   |-------|--------------|-------------------|---------------|--------|
   | {name} | {weekly_output} | {weekly_heartbeats} | {weekly_util} | {status} |

6. If `last_weekly_report` was `never` (first run): skip delta calculation, write current values as baseline, and note "First weekly snapshot recorded. Deltas available next week."

7. Update "## Weekly Snapshot" in MEMORY.md with current lifetime counters for all 14 agents.
8. Set `last_weekly_report` to today's date.

### Consolidation Recommendations (CONS-02)

1. Read "## Underutilisation Tracker" from MEMORY.md.

2. For each agent flagged as `UNDERUTILISED` this week:
   - Check if agent is in the Exceptions list (CEO, CMO, CTO, Product Owner). If so, skip.
   - Increment their `consecutive_weeks_under` counter by 1.
   - Update `lifetime_heartbeats_at_last_check` with current value.

3. For each agent NOT flagged as `UNDERUTILISED` this week: reset their `consecutive_weeks_under` to 0.

4. Check recommendation thresholds:
   - **Standard agents:** `consecutive_weeks_under` >= 3 AND `lifetime_heartbeats_at_last_check` >= 15
   - **Reactive roles** (Code Reviewer, Quality Reviewer): weekly_util < 10 for 5+ consecutive weeks AND `lifetime_heartbeats_at_last_check` >= 25

5. For each agent meeting the threshold:
   a. Read their skills from `$AGENT_HOME/../{agent-dirname}/AGENTS.md`
   b. Check if another agent in the same department has overlapping skills (read peer AGENTS.md files)
   c. If skill overlap exists: recommend MERGE
      - Comment: `[CONS-MERGE] Recommend merging {agent name} into {absorbing agent}. Reason: {weeks} consecutive weeks below utilisation threshold. Skills overlap with {agent name}.`
   d. If no skill overlap: recommend RETIRE
      - Comment: `[CONS-RETIRE] Recommend retiring {agent name}. Reason: {weeks} consecutive weeks below utilisation threshold. No skill overlap with department peers.`
   e. Create a board issue for approval:
      `POST /api/companies/{companyId}/issues` with title `[BOARD] Consolidation recommendation: {MERGE/RETIRE} {agent name}` and the recommendation details in the description.

6. Update "## Underutilisation Tracker" in MEMORY.md with current counters.

### Skill Redistribution Plan (CONS-03)

For each CONS-MERGE or CONS-RETIRE recommendation generated above:

1. Read the target agent's `AGENTS.md` to list all their skills.
2. Read `.planning/skill-ownership-matrix.md` for the full skill mapping.
3. For each skill owned by the target agent, identify the best absorbing agent:
   - Same department preferred (business stream agents absorb business skills, tech stream absorbs tech skills)
   - Agent with complementary (not duplicate) skills preferred
   - Agent with utilisation < 80% preferred (has capacity)

4. Add the redistribution plan to the board issue description:

   ```
   ## Skill Redistribution Plan: {agent name}

   | Skill | Recommended New Owner | Rationale |
   |-------|-----------------------|-----------|
   | {skill name} | {absorbing agent name} | {reason: same dept, complementary skills, has capacity} |

   **Action required:** Board approval before any agent changes. This is a recommendation only.
   ```

5. NEVER execute merge or retire without board approval. The CEO creates the recommendation and board issue; Martyn decides.
```
