**E2E-04: Stall Detection Under Simulated Failure**

**Critical timing note:** Stall detection checks elapsed time between the issue's last activity and the current heartbeat. Running CMO heartbeats back-to-back will NOT trigger stall detection because no real time elapses. You MUST either:
- Option A: Wait 5+ minutes between each CMO heartbeat run (slower but realistic)
- Option B: Use API PATCH to backdate the issue's `updatedAt` timestamp between heartbeat runs (faster, recommended)

**Steps:**
1. Create a clearly routine content issue assigned to Customer Success (6003d629-f007-49f6-8530-1168f18f2159):
   ```
   npx paperclipai issue create -C "$COMPANY_ID" \
     --title "VALIDATION: Research competitor recruitment landing pages and summarise key messaging patterns" \
     --description "E2E-04 stall detection test. Routine research task. DO NOT run Customer Success heartbeat. CMO should detect stall after repeated heartbeats and escalate via 2-nudge protocol: [STALL-NUDGE-1] then [STALL-NUDGE-2] then [STALL-REASSIGN]." \
     --priority medium \
     --assignee-agent-id 6003d629-f007-49f6-8530-1168f18f2159
   ```
2. Record the created issue ID.
3. **DO NOT** run Customer Success heartbeat. This simulates failure.

**Heartbeat cycle with timing (Option B - API backdate):**

4. Run CMO heartbeat 1: `npx paperclipai heartbeat run -a 293ac1cb-098c-4fc7-83dc-3ef8b805c8db`
   - Expected: No stall yet (issue just created, first check cycle)
   - After heartbeat, check comments on the test issue

5. Backdate the issue's updatedAt to simulate 2+ heartbeat cycles elapsed:
   ```
   curl -s -X PATCH "http://localhost:3100/api/issues/<issueId>" \
     -H "Content-Type: application/json" \
     -d '{"updatedAt": "<timestamp-30-minutes-ago-ISO8601>"}'
   ```
   Use a timestamp 30 minutes in the past (e.g., calculate with `date -u -v-30M +"%Y-%m-%dT%H:%M:%SZ"` on macOS).

6. Run CMO heartbeat 2: `npx paperclipai heartbeat run -a 293ac1cb-098c-4fc7-83dc-3ef8b805c8db`
   - Expected: [STALL-NUDGE-1] comment appears on the issue
   - Verify: `curl -s "http://localhost:3100/api/issues/<issueId>/comments" | jq '.[].body | select(contains("STALL-NUDGE-1"))'`

7. Backdate the issue updatedAt again (another 30 minutes back from current time).

8. Run CMO heartbeat 3: `npx paperclipai heartbeat run -a 293ac1cb-098c-4fc7-83dc-3ef8b805c8db`
   - Expected: [STALL-NUDGE-2] comment appears
   - Verify: `curl -s "http://localhost:3100/api/issues/<issueId>/comments" | jq '.[].body | select(contains("STALL-NUDGE-2"))'`

9. Backdate the issue updatedAt one more time.

10. Run CMO heartbeat 4: `npx paperclipai heartbeat run -a 293ac1cb-098c-4fc7-83dc-3ef8b805c8db`
    - Expected: [STALL-REASSIGN] comment appears (routine work auto-reassigned to another idle report)
    - Verify: `curl -s "http://localhost:3100/api/issues/<issueId>/comments" | jq '.[].body | select(contains("STALL-REASSIGN"))'`
    - Also check if assigneeAgentId changed to a different agent

**If API PATCH for updatedAt doesn't work (field may be read-only):**
- Fall back to Option A: wait 5+ minutes between each CMO heartbeat
